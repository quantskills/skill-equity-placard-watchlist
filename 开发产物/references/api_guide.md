# 数据接口指南 · skill-equity-placard-watchlist（#17）

> 所有结论均来自**真机实测**（PandaData 真实调用），非文档臆断。

## 一、清单点名的接口不存在（必须先说清楚）

任务清单 #17 写的接口是 `get_stock_equity_placard`。核对 PandaData **最新接口文档（187 方法）**：

```
get_stock_equity_placard        ❌ 命中 0 次
"举牌"                          ❌ 全文 0 次
"权益变动"                      ❌ 全文 0 次
"一致行动"                      ❌ 全文 0 次
```

**结论**：PandaData 没有现成的举牌数据表。举牌事件只能从**十大股东持股比例快照**重建
——同一股东的持股比例在相邻报告期之间上穿 5% 及其梯度，即为举牌。

这不是实现取巧，而是数据可得性决定的唯一路径；由此产生的"报告期快照口径、非实时播报"限制已在
SKILL.md / README 显著位置声明。

## 二、`get_top_holders` 字段与实测

### 入参

| 字段 | 说明 |
|---|---|
| `symbol` | 股票代码；**传 `''` 可一次拉全市场**（实测 2025-01-01~2026-07-21 得 551,691 行 / 5,240 只 / 63 秒） |
| `start_date` / `end_date` | 按**公告日**筛选（YYYYMMDD） |
| `stock_type` | `total`（基于全部已发行 A 股）/ `flow`（基于流通 A 股） |
| `start_rank` / `end_rank` | 排名区间 |

### 响应字段（实测）

| 字段 | 实测说明 |
|---|---|
| `date` | **公告日** —— 本 skill 的 PIT 基准（`trade_date`） |
| `end_date` | **报告期截止日** —— 持股数据所属期（`as_of_date`） |
| `holder_name` | 股东名称 |
| `hold_percent_total` | 持股比例（%）——**含义随 `stock_type` 变化，见下方陷阱** |
| `hold_percent_float` | 占流通 A 股比例（%） |
| `rank` | 排名 |
| `holder_kind` | 股东性质（一般企业 / 开放式投资基金 / 自然人 / 保险投资组合 / 基本养老保险基金 / 投资咨询公司 …） |
| `holder_attr` | 股东属性（企业 / 证券品种 …） |
| `pledge` / `freeze` | 质押 / 冻结股数（本 skill 未使用） |

## 三、【陷阱 1】`stock_type` 双口径 —— 同名字段不同含义

不指定 `stock_type` 时接口**同时返回两套行**。实测 002011.SZ（盾安环境）：

| end_date | holder_name | stock_type | hold_percent_total | hold_percent_float |
|---|---|---|---|---|
| 20241231 | 珠海格力电器 | `flow` | **25.38** | 29.51 |
| 20241231 | 珠海格力电器 | `total` | **38.46** | 29.51 |

格力 2021 年收购盾安环境约 **38%** 股权是公开事实 → **`total` 行才是占总股本的真实比例**，
`flow` 行的 `hold_percent_total` 实为在流通股本上计算的值。

举牌线按《证券法》是**已发行股份的 5%**，故必须 `stock_type == 'total'`。
用错行会让整个举牌梯度判定系统性偏低。

> 附注：当限售股全部解禁后（流通股本 = 总股本），两套行数值会重合。实测 002011.SZ 20260331
> 两者同为 38.13%，这也侧面印证了上述解释。

## 四、【陷阱 2】一个公告日携带多个报告期

实测 002011.SZ `date=20240419` 的返回里同时含 `end_date=20231231` 与 `end_date=20240331` 两个报告期，
`rank` 因此出现重复值（rank 3、6、7、8 各出现两次）。

**处理**：按 `(symbol, holder_name, as_of_date)` 去重，保留**最早公告日**（首次披露即 PIT 时点）。
并且 `as_of_date` 必须进主键，否则不同报告期的事件会互相覆盖（实测丢失 12 条）。

## 五、【陷阱 3】报告期不只有季度末

实测 `end_date` 取值除 `0331/0630/0930/1231` 外，还有 `20260414`、`20260420`、`20260717` 等
**非季度末日期**——多为股东大会股权登记日等特殊登记时点。

这带来的是**更细的时间分辨率**（好事），但也意味着相邻"期"的间隔不均匀。
本 skill 不做等间隔假设，仅按 `as_of_date` 排序求相邻期变动。

## 六、【陷阱 4】股本变动造成的被动比例变化

见 `quality_evidence.md` 第二节。核心：总股本变化时所有未交易股东的比例被**同一系数整体缩放**，
必须先推断该系数再判定越线，否则增发会被全量误报成"减持跌破"。

## 七、性能与配额

| 操作 | 实测 |
|---|---|
| 全市场 `symbol=''`，5 天窗口 | 119,499 行 / 27.7 秒 / 3,997 只 |
| 全市场 `symbol=''`，1.5 年窗口 | 551,691 行 / 63 秒 / 5,240 只 |
| 单票 1.5 年 | 133 行（`total` 口径去重后） |

全市场一次拉取远快于逐票循环，故 `scan` 模式直接用 `symbol=''`。

## 八、凭证

一律走环境变量 `PANDA_USERNAME` / `PANDA_PASSWORD`，或官方文件 `~/.pandadata/pandadata.env`
（键名为 `DEFAULT_USERNAME` / `DEFAULT_PASSWORD` / `JAVA_SERVICE_BASE_URL`）。**绝不硬编码。**
